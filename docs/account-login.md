# 帳號不分大小寫

登入帳號以 `trim().toLowerCase()` 比對，例如 `duncan`、`DUNCAN`、`DuNcAn` 視為相同；密碼與 PIN 的比對維持原有規則，不轉換大小寫。暱稱登入保留原本的精確比對。

既有帳號的 `users.accountId` 不改寫。即使舊帳號是 `TiNa`，輸入 `TINA` 登入後，session 和群組查詢仍使用原始 `TiNa`，保留群組 members、遊戲、待辦等使用帳號 ID 的關聯。

一般註冊和管理者新增成員共用 `js/account-identity.js`：

- 新帳號限英文、數字、底線，統一儲存為小寫。
- 建立前讀取 users 比對所有既有 accountId，包含其他群組與舊版混合大小寫的帳號。
- 新帳號使用固定文件路徑 `users/account_<小寫帳號>`，並在 Firestore transaction 內重新確認文件不存在再建立。兩個新版入口同時註冊不同大小寫的同名帳號時，只能有一個成功。
- 管理者新增同時寫入目前群組的 members；新個人資料與群組成員關係皆在同一交易內建立。
- 已設定的帳號 ID 不能由成員編輯流程修改；顯示名稱仍可編輯。

因舊帳號沒有正規化索引，帳號查找目前需要讀取 users 集合，才能完整涵蓋既有任意大小寫。未來若帳號量增加，可先建立正規化索引再改為索引查找；不可直接只查小寫值，否則舊帳號將無法登入。

若既有資料已包含大小寫不同的同名帳號，登入會顯示需管理員確認的訊息，不自動選取其中一人的資料；本次程式修改不會自動合併既有帳號。沒有更動正式環境資料或新增集合。

驗證：

- `node tests/account-login.cjs`：真實登入／註冊表單，使用隔離 Firestore，涵蓋混合大小寫、舊 ID／群組、密碼大小寫、PIN／暱稱／記住帳號、重複與同時註冊、失敗重試。
- `node tests/admin-members.cjs`：管理者新增大小寫正規化、跨群組重複阻擋與成員管理回歸。
- `node tests/group-switch.cjs`、`node tests/mobile-app.cjs`：群組切換及手機導覽回歸。

以上測試皆使用本機靜態站台（預設 http://127.0.0.1:8012）及測試資料，不存取正式 Firebase。
