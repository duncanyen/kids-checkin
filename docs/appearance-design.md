# Nexus 外觀與顏色主題

## 介面盤點與設計依據

依使用者提供的五張參考圖與現有程式進行介面盤點：舊版混用了 emoji、日期圖示、彩色底座與漸層；主頁與功能頁各自定義相同顏色，許多白底與灰字寫死在樣式內。只替換主色會造成深色背景下的白色卡片、讀不清的文字與不一致的導覽。

這次以暖白背景、圓角白卡、淡色圖示底座、24px 同筆觸 SVG 線條圖示，以及較清楚的留白建立共用視覺。主頁、側選單與底部導覽使用同一圖示來源；保留上傳頭像、使用者自選群組圖示、照片、遊戲繪圖與資料內容。個人設定增加個人資料摘要及「外觀與主題」區塊。

可用主題：蜂蜜（預設）、胡桃、茜紅、淺青、紫藤、香橙、靜海，以及深色的琉璃藍、葡萄、常青。全部開放選擇，未加入參考圖的付費鎖。參考圖的淡金色保留於裝飾色，主要操作色改用更深的金棕，確保小字可讀。深色主題的按鈕則使用淺色底與深色文字。

設計參考：

- [WCAG 2.2 文字對比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：一般文字對比至少 4.5:1。測試十款主題在頁面／卡片上的主文字、次文字，以及主要按鈕文字。
- [WCAG 2.2 目標尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)：最小點擊目標與間距；新的設定操作採至少 44px 高的觸控目標。
- 選取狀態同時呈現勾選、外框與文字；支援鍵盤方向鍵、焦點輪廓、狀態朗讀與減少動態效果。主頁進場不再以 transform 造成固定底部導覽錯誤地依附卡片容器。

這是參考圖分析與程式盤點，並未進行訪談或正式使用者研究；核心色票對比測試不代表整個應用已通過無障礙認證。

## 使用流程

個人設定 → 顏色主題設定 → 點選色卡即時預覽 → 儲存主題。還原會返回已儲存色彩；預覽不寫入本機或雲端，離開頁面也不保留。儲存失敗會保留預覽並顯示重試提示，不宣告儲存成功。

沿用 `userSettings/{accountId}`，以合併寫入保存：

```json
{"accountId":"原有穩定帳號","appearance":{"theme":"honey","version":1}}
```

卡片排序 `order`、顯示設定 `modules` 與其他欄位不受影響。個人主題跨群組一致，不以會變動的姓名作 key。讀取雲端偏好沿用主頁／個人設定原本的 `readPersonalLayout`，不新增常駐監聽或各功能頁資料庫讀取。跨裝置於進入主頁或個人設定時取得雲端設定。

`theme-bootstrap.js` 在頁面樣式之前執行，同步讀取目前帳號的本機快取 `nexus.appearance.v1:{accountId}`，提供跨功能頁與離線顏色。切換帳號不沿用別人的偏好。無快取、資料毀損、儲存空間被封鎖或不支援的主題代碼都安全回退；雲端錯誤不自動寫入預設主題。

套用頁面：主頁、個人設定、待辦、行事曆、聊天室、相簿、記帳本、吃什麼、通知、遊戲入口、許願牆、打卡、管理者後台。咕咕村落與寵物遊戲保留其專用遊戲美術。主題只處理外觀，不新增參考圖中尚未存在的字體／語言／訂閱設定。

## 維護與驗證

- `js/theme-bootstrap.js`：色票、相容變數、帳號快取與首屏套用，不依賴 Firebase。
- `css/nexus-theme.css`：共用介面及舊功能頁色彩對接；功能頁原有中性色改為語意色變數。
- `js/ui-icons.js`：本機 SVG 圖示、導覽鍵盤操作，未引入第三方圖示 CDN。
- `js/appearance-settings.js`／`css/appearance-settings.css`：選擇、預覽、還原、儲存、失敗處理。
- `node --test tests/theme.test.cjs`：十款色票對比、本機失敗回退、預覽與帳號隔離。
- `node tests/theme-browser.cjs`：真實頁面預覽、儲存與重試、排序欄位保留、跨頁與帳號切換、鍵盤操作、手機／桌面寬度。Firestore 使用隔離模擬資料，未寫入正式資料庫。

本次不需新增 Firebase 後端函式；沿用既有 `userSettings` 權限。正式規則及跨實體裝置同步尚須在實際部署環境驗證。
