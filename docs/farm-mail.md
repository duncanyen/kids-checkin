# 咕咕村落通知

右下角信封按鈕開啟「通知」，使用與村落一致的木質、羊皮紙介面。訪客／系統分頁各自列出通知，由新到舊排列，時間固定為台灣時間 `YYYY-MM-DD HH:mm:ss`。開啟時暫停遊戲的滑鼠／觸控輸入，遊戲時間、天氣及戰鬥倒數仍繼續；關閉時還原輸入。

## 資料與一次性獎勵

- 通知存於 `groups/{groupId}/users/{accountId}/farm_notifications/{notificationId}`，對應目前選擇的群組及固定帳號。
- 成功載入自己的農場後，以交易寄送固定 ID `welcome-v1` 的系統通知。主旨「系統通知」，內文「歡迎加入咕咕村落，若您有任何疑問，歡迎隨時與我們連絡，感謝您的支持，祝您遊戲愉快」。
- 獎勵是 1000 金幣、8 隻菜蟲、4 隻蚯蚓，加入既有 farm.coins／worms／earthworms。領取交易讀取最新餘額，連同通知 claimedAt 與農場文件的 farmMail.welcomeClaimedAt 一次寫入，多分頁同時領取也只生效一次。
- 農場文件另存 farmMail.welcomeCreatedAt，刪除通知不刪除寄送／領取紀錄。因此刪除後或重新進入都不會補發；未領取就刪除會先警告放棄獎勵。每個群組的遊戲帳號各自獨立。
- 獎勵比照既有首領掉落，不受倉庫上限攔截。初始容量 10 小於獎勵的 12 隻蟲，仍可完整領取，超量後需餵食或整理才能繼續取得一般物品；介面有提示，不會自行增加容量。
- 有 reward 且尚未 claimedAt 的項目右側顯示禮物。系統項目可開啟內文、獎勵及刪除按鈕；訪客項目只有主旨、註記、時間和刪除鈕，不提供內文頁。

## 訪客

只有成功偷走一顆蛋，才在被偷者所屬群組的通知子集合新增一筆「訪客來訪／訪客來偷蛋」。不寫入偷蛋者姓名或 accountId。隨機通知 ID 與時間在交易外產生，交易重試不會產生重複通知；通知、扣除目標雞蛋、增加偷蛋者庫存及冷卻紀錄在同一交易提交。失敗、冷卻中、倉庫已滿、空雞舍與交易失敗不新增通知。

既有群組聊天室的遊戲系統訊息保持原流程，與個人的訪客通知分開。

## 權限及讀取

寄送、領取、刪除前會重新驗證 groups.members；跨村偷蛋仍使用既有 readVillageAccess，重新檢查雙方公開設定及成員資格。通知只在信箱開啟時監聽，關閉立即解除；寄送歡迎信的狀態直接由既有農場監聽觸發，不增加常駐通知 listener。通知目前使用 Firestore，與 RTDB 切換開關無關。

本專案未納入正式 Firestore Rules。上線時需確認既有規則允許本人讀取／刪除通知、合法偷蛋交易在目標通知子集合建立訪客紀錄，並保護寄送及領取紀錄。客戶端交易可防正常操作下的競爭重領，無法取代伺服器權限驗證；與現有遊戲經濟相同，若要防止修改客戶端偽造金幣，應由受信任後端處理獎勵及經濟交易。

## 驗證

```sh
node --test tests/farm-mail.test.mjs
FARM_BASE_URL=http://127.0.0.1:8012 node tests/farm-mail-browser.cjs
```

測試使用隔離資料，沒有正式資料庫讀寫。涵蓋並行寄送／領取、已滿倉庫、領取失敗重試、刪除前後不補發、群組獨立、被移除成員拒絕、匿名及台灣時間；實際 Phaser／手機尺寸頁面另驗證分頁、內文、禮物提示、已領取鎖定、重新整理、輸入隔離，以及成功／失敗偷蛋的原子寫入。
