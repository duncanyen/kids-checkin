# 怪物只在進場判定

## 原因與調整

先前自家收蛋會呼叫 `homeEncounter` 抽怪；拜訪偷蛋的驗證若遇到其他分頁改寫許可，也可能重新抽怪。抓菜蟲前後另會檢查地鼠里程碑，因此玩家可能先看到操作中提示，才突然進入戰鬥。

現在：

1. `MyFarmScene.startEntryEncounter()` 在自家場景取得存檔後，統一檢查里程碑及一般怪物；`VisitScene.startVisitEncounter()` 在拜訪進場時完成檢查。
2. `entryChecked` 與 `checkingEntry` 控制進場是否完成。慢連線、怪物素材載入、戰鬥及後端結算期間，攔住收蛋、偷蛋、清潔、治療與抓蟲。戰鬥物件維持可攻擊，原有返回／溜走流程保留。
3. 收蛋及偷蛋送出 `verifyOnly:true`，伺服器只接受目前雞舍已清場／已結算的許可，不抽新怪。許可被其他分頁改到別處時拒絕此次操作，提示重新進入村落，不能在操作中補抽一隻怪物。
4. 同次停留可重複完成有效收蛋；不因前一筆收蛋消耗許可就重新抽怪。既有原子交易、收據、防重、守衛犬、冷卻、入庫、排行及任務計次沿用。
5. 地鼠／蛇王／巨人的新里程碑只在進場檢查，操作達標後延到下次進場。不改門檻、血量、傷害、獎勵或機率數值。
6. 自家進場的一般怪物判定不再以有待收蛋及倉庫有空間為前提。判定時間移到進場，不在按收蛋後才判定。
7. 未結算戰鬥由進場的權威回覆恢復，保留原 ID、血量、期限與損失目標。移除通知快照另外啟動恢復的競態，避免同時恢復／結算兩次。
8. 偷蛋逾時確認仍使用原 action、payload 與 ID；讀取升級前留下的 pending 請求時，也不擅自新增旗標而改變收據指紋。

`verifyOnly` 是既有交易的可選布林欄位。未帶旗標的舊客戶端保留相容行為；所有新版收蛋／偷蛋入口均帶旗標。這不是把前端旗標當成授權，後端仍驗證身分、群組、戰鬥、許可、冷卻與庫存。

## 驗證

350 項 Node 測試通過。新增測試涵蓋：

- 新進場可生成怪物，即使沒有待收蛋。
- 進場清場後，即使亂數刻意設為必出怪，連續收蛋與偷蛋仍只收取／偷取，不產生怪物。
- 缺少或不相符的進場許可拒絕操作，不因此抽怪。
- 所有六種 Boss 與野狼／老虎，以及後端結算期間，其他農場物件均被阻擋。
- 怪物未結算時，直接呼叫清潔或抓蟲也會被後端拒絕。

真實 Phaser 3.60.0＋隔離 Firebase SDK／MemoryDB 整合通過：

- 延遲自家進場驗證，確認回覆前收蛋、清潔、抓蟲不送出交易。
- 自家進場先出現猩猩，戰鬥期間農場操作不送交易；結算後可收蛋，且不重抽怪。
- 從原 HUD「村落 → 公開村落 → 村落卡片 → 玩家雞舍」入口進入，地鼠於進場出現；偷蛋、協助清潔、抓蟲均被阻擋。
- 抓蟲達門檻時不開地鼠；下次進場才出現地鼠。
- 戰鬥結算後點原雞隻可偷蛋，回傳成功結果，沒有產生新怪物。
- 收蛋結果面板的單／多雞種、容量、失敗與清理回歸。
- 拜訪驗證的延遲、跨分頁許可失效、原目標逾時損失、重試及野狼回歸。
- 偷蛋的延遲提示、快速連點、逾時同 ID 確認與重新整理防重回歸。
- 自家與拜訪未結算戰鬥可恢復，重新整理不重置血量／期限；逾時損失仍屬於原雞舍。
- 商店、餵食、清潔、實際怪物命中／結算及每日任務整合回歸。

## 修改檔案

- `js/farm/MyFarmScene.js`、`js/farm/VisitScene.js`：進場判定、操作接線與恢復流程。
- `js/farm/entry-encounter.js`：共用農場操作阻擋條件。
- `js/farm/hud-ui.js`：進場未確認時隱藏導覽。
- `js/farm/backend-client.js`：尋回新版及舊版 pending 偷蛋請求。
- `game-admin/functions/farm-combat.cjs`、`farm-transactions.cjs`：驗證模式與已清場許可。
- `game-admin/tests/entry-encounters.test.cjs`、`tests/farm-entry-encounter.test.mjs`、`tests/farm-private-backend-browser.cjs`。
- 本報告及截圖。
