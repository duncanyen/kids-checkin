# 進入村落時 ensureWelcome 回傳 400

2026-11-14（台灣）。使用者實際訊息為 `ensureWelcome`／`functions/failed-precondition`／「請先完成怪物戰鬥結算」。

## 原因與修正

- 通知會在玩家存檔載入後自動準備。舊後端把 `ensureWelcome` 視為需先完成戰鬥的經濟操作，未結束的戰鬥因此阻擋通知。
- `ensureWelcome` 只建立通知及獨立歡迎禮收據的準備標記，不直接增加金幣或物品；本次允許它在戰鬥中執行。`claimWelcome`、餵食、買賣及收蛋仍保留原本的戰鬥限制。
- 正常怪物的原會話保留在後端，但重新開啟自家時，舊前端不一定把它恢復為可見戰鬥。通知回覆現在順帶提供該玩家的未完成會話，前端使用原 ID、目標、血量及截止時間恢復，不另外抽怪或自動收蛋。
- 拜訪戰鬥回到原村落繼續。已逾時或已被伺服器確認打敗的會話直接經後端結算，沿用既有損失／獎勵規則；不重設計時，也不重新處罰已結算的同一會話。
- 通知收據重送仍防重；回傳的戰鬥提示會重新查詢目前狀態，避免重播已結束的舊怪物。
- 不變更 Firestore 結構、Rules、玩家資產設定、怪物數值或歡迎禮金額。

## 驗證

- 317 項單元測試通過；新增戰鬥中準備通知不發獎、經濟操作仍被擋，以及收據不恢復舊戰鬥的測試。
- 真實 Phaser 3.60.0＋隔離 SDK／資料庫：自家與拜訪的未完成戰鬥均可恢復原血量與期限、重新整理後繼續、逾時僅結算一次，結算後可餵食。
- 一般進入、合併收蛋、倉庫餵食與戰鬥／每日任務的既有隔離瀏覽器流程通過。
- 真實 Auth／Functions／Firestore Emulator 合約測試已補入戰鬥中 `ensureWelcome` 成功且不發獎、`claimWelcome` 仍被拒絕。本環境 Emulator 下載受 HTTP 403 網路政策限制，此新合約需在 Cloud Shell 執行，不能視為已通過。

## 發布

GitHub Pages 發布前端後，仍須在 Cloud Shell 驗證並更新 `game-admin` 的 `functions:nexus-ops`；只推送 GitHub 不會修正正式後端的阻擋。無須重跑帳號遷移、`purge`／`activate` 或部署 Rules。

正式驗收：強制重新整理並進入自己村落，確認沒有 `ensureWelcome` 的 400；如有未完成戰鬥，確認原戰鬥恢復或依期限結算，之後再測試餵食。不得刪除戰鬥紀錄或直接調整金幣作為修正方式。
