# 記帳清單

清單模式為記帳本的預設入口。單一原生年月選擇器顯示「2026年11月」，左右按鈕前進／後退一個月；手機的年月挑選介面由系統提供。支出頁只顯示右下「+」，收入頁只顯示左下「+」，收入沿用既有權限。

明細每頁 10 筆，依日期及文件 ID 降冪排序。Firestore 查詢使用 `limit(10)` 與文件快照游標；不預先下載後續頁面，上一頁使用本次瀏覽的快取。切換月份／收支類型、新增或刪除時清除快取。當月金額及總筆數使用伺服器端 sum/count，不下載整月文件。月曆及回顧只在使用者切換到該模式後讀取。

一般紀錄會在資料庫依收支類型篩選後讀取 10 筆。舊紀錄若缺少 type 欄位，仍視為支出；僅這類月份的支出使用每批最多 10 筆的有界串流，略過收入並填滿當前頁，可能需多個批次。收入始終在伺服器篩選。若要連舊月份也嚴格每頁只讀取一次 10 筆，需要另行核准將缺少 type 的正式資料補為 expense；本次不自動修改正式歷史資料。

新增紀錄後回到第一頁並重取當月彙總，避免顯示過期總額。清單彈窗中的「本頁當日明細」僅包含本頁資料；完整日曆明細仍可從月曆模式查看。

## 上線

新增查詢需要 Firestore 複合索引，已列於 `firestore.indexes.json` 並由 `firebase.json` 引用。用具備 homebasedb 索引管理權限的帳號執行：

```sh
firebase deploy --only firestore:indexes --project homebasedb
```

確認索引建置完成後再發布前端。未在此任務部署索引或操作正式資料；缺索引時清單顯示讀取失敗與重試，不退回整月下載。

## 驗證

```sh
python3 -m http.server 8012 --bind 127.0.0.1
node tests/expense-list-browser.cjs
TEST_MODE=chart node tests/navigation-loading.cjs
```

測試使用隔離 Firebase 資料，涵蓋每次明細查詢上限、25 筆資料分頁、按需讀取與上一頁快取、舊資料、月總額、新增刪除與網路失敗。

## 2026-11-06：新增按鈕與空白名稱

清單模式的收入／支出圓形新增按鈕共用右側定位，切換類型不改變位置，仍避開底部導覽列。名稱留空時，清單與當日明細都顯示空白，不顯示「未填寫名稱」或「補上名稱」。明細保留有無障礙名稱與點擊範圍的空白編輯按鈕，可之後補填。

`note` 明確為空字串或 null 時維持空白；只有舊資料完全沒有 `note` 欄位時才讀取舊 `name`，避免清空後復活舊名稱。金額、分類與選填規則不變。

`tests/expense-list-browser.cjs` 驗證空名稱、新增與補填、320／390／768px 的收入／支出按鈕同位、底部導覽避讓及既有交易／權限流程，使用隔離 Firebase fixture。
