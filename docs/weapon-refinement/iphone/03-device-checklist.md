# 需由您親自操作的實機清單

目前所有實機案例初始為 **NOT_RUN**。我們已做Chromium預檢；下列Safari／PWA結果只能由實際iPhone操作後填入。

先記錄：iPhone型號、iOS版本、Safari版本（若可見）、是否Safari／主畫面PWA、Wi-Fi或行動網路、runId、來源commit／sourceCodeSha256、測試開始時間（台灣時間）。第一輪先做PRE-01、UI-01、SHOP-01、TAB-01。

## 第二輪：回應遺失、斷線、更新

控制面板請先開另一頁保留同假帳號。不要在操作已送出後才設定下一筆故障。

| ID | 您要操作的步驟 | 通過標準／應保存證據 |
| --- | --- | --- |
| REC-01 | 面板選購買武器／後端成功回應遺失→套用。回商店買一把狼牙棒，看到結果確認中後按確認原交易 | 後端只扣一次，查詢不再買一把；原ID不變；返回村落、倉庫正確。保存含injected=lost的JSON |
| REC-02 | 選購買武器／尚未執行即失敗→套用。買武器後按確認原交易；先不要重試，等5秒，再查看狀態 | 餘額不動，仍結果未明，不自動送新購買；再明確按以原請求重試，只扣一次，ID沿用。JSON需能看見before及retry |
| REC-03 | 選購買武器／延遲2秒→套用；快速連按確定 | 立即有處理中回饋，沒有新ID連續扣款；結果回來才更新。此延遲是注入，不混入正常網路P50/P95 |
| NET-01 | 在可操作頁開飛航模式，嘗試一次操作，等提示後恢復網路，按確認原交易 | 不顯示假的成功；保留原ID；結果未明時不自動新扣款。記錄飛航開始／恢復時間 |
| UPDATE-01 | 面板選進入自家村落／要求更新→套用；回遊戲重新進入自家村落 | 出現更新遮罩，背後操作不能繼續；文字、兩顆按鈕在小螢幕可見 |
| UPDATE-02 | 更新遮罩出現後開飛航，再按檢查並更新；恢復網路後重試 | 離線更新應失敗且保留原紀錄，不清資料、不假裝完成；連線後可更新並回正常頁。更新前後JSON／畫面 |
| CLOSE-01 | 面板選回應遺失並完成一次假購買；出現確認中時從App切換器強制關閉Safari／PWA，再重新開啟同身分 | 同run不重啟server；原操作只一次扣款。若儲存容器改變或瀏覽器未保留pending而無法自動確認，記FAIL／限制，不能改ID重買或清資料補成通過 |
| BACKGROUND-01 | 操作中切到其他App約30秒後回來；另測鎖屏約30秒 | 不重複扣款；若頁面被作廢應明確要求重新進入，不自動恢復舊戰鬥並發獎 |

**提醒：**真斷線的請求可能在斷線前已送達。只能用收據判定，不能用手機顯示失敗就判定未扣款。伺服器受控故障是可重現測試，真飛航操作是實機網路測試，兩種分開記錄。

## 第四輪：主畫面PWA與網路樣本

1. **您操作：**Safari分享→加入主畫面，名稱應為「咕咕驗收」。不要覆蓋正式Nexus捷徑。
2. **您操作：**從主畫面啟動，若此容器尚未選假帳號，再選同一個小咕A；下載狀態，確認runId相同。首頁報告的standalone應為true。
3. **您操作：**重做SHOP-01、REC-01、UPDATE-02與BACKGROUND-01。Safari與PWA儲存是否共享要如實記錄，不能預設跨容器有同一個鎖／sessionStorage。
4. **您操作：**在Wi-Fi做至少20次可辨識操作、行動網路再20次；正常樣本不注入故障。分別記錄請求送出至回應的中位數、P95，以及主觀操作卡頓／損幀。可先每網路5次做可用性預檢，樣本不足就標不足。
5. **我們整理：**用JSON中的clientMetrics／server records對齊原ID；注入2秒、回應遺失、重試及冷啟動另外分組，不混入正常樣本。此站是MemoryDB＋HTTP adapter，數值只能描述驗收站與此手機網路，不能代表正式Firestore／Functions區域延遲。

## 統一停止條件

發現負數、武器遺失／重複、同ID重扣／重退、錯誤群組資產、未結算就成功入庫，立即停止後續案例，保存螢幕錄影＋JSON。不要重啟server、清資料、重新買一次或手改餘額補救。

正式Auth／權限、正式Rules、真歷史舊PWAartifact升級與實際雲端負載，仍為獨立待驗項。此清單不授權正式部署，也不把所有手機案例自動標PASS。
