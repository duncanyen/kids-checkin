# 進場前攻擊限制修正與後續方案

日期：2026-11-28（台灣時間）。本次完成工作目錄修正與隔離測試；未部署、未讀寫正式資料、未提交或推送 Git。完整發布仍 NO-GO。

## 已實作

- 在 `combat-damage.js` 新增共用純函式 `battleAttackAvailable(battle, now)`。
- 後端 `farm-combat.cjs` 在原攻擊交易內使用可信任會話的 `approachEndsAt` 與伺服器時間檢查。早於進場完成即拒絕，不扣HP、不建立成功收據、不發獎；客戶端傳入的時間不會放行。
- 前端 `backend-client.js` 在預測傷害、命中回呼與排隊前先檢查；進場中的武器模式切換也不排入批次，避免純切換在等待期間產生被拒絕的批次。
- `dragon.js` 的共用Boss近戰／弓箭命中處理加同一檢查；點擊過早時限頻提示「怪物進場中，抵達後可攻擊」，不刷出一排浮字。
- `archery.js` 在進場中不讓玩家開始拉弓／放箭，並顯示相同提示。
- 到 `approachEndsAt` 的精確邊界即可攻擊；到 deadline 仍按原規則逾時，沒有額外強制等待動畫。

前端檢查只改善體驗，後端仍是安全邊界。即使舊版或被改過的客戶端直接送攻擊，也受後端檢查。

沒有調整上述時限、HP、原始傷害、爆擊、攻速、武器相容性、任務或獎勵。此修正會消除先前可提前攻擊的收益，例如金剛實際可輸出時間是原40秒中的30秒；沒有偷偷延長deadline。後續仍需評估低階武器在合法窗口的通關率，不因安全修正而擅自改平衡。

每約500ms合併攻擊、本機即時回饋、後端最終血量／獎勵與原交易防重保持。不新增每下攻擊的Firestore讀取或網路往返；後端只對已讀取的會話增加一次純判斷。

未保存進場欄位的歷史會話保留舊資料相容，不猜測補時間；新會話皆由後端提供。已完成的舊收據仍回傳原結果，不反向扣除玩家舊資產。

## 驗證

新增共用 MemoryDB／真實Firestore案例：V4與V5均驗證開始時／邊界前1ms拒絕，偽造payload時間無效、無成功收據、無資產／HP變動、無法提前結算；精確邊界合法，deadline拒絕。純函式另測九種怪物、零進場時間與無效數值／舊資料。

先前的SEC-02重現已改為回歸：開戰後2秒的25次偽造攻擊被拒絕，金剛HP保持原值且無戰利品。**抵達後仍可送出額度內但沒有碰撞證據的25次攻擊得獎（SEC-01），這部分刻意繼續重現並列阻擋。**

原單元測試中8項曾假設怪物抵達前即可攻擊，現在測試時鐘先前進到真實會話的approachEndsAt再測傷害、速率、任務與防重；未放寬正式限制。初跑與修正紀錄保留。

瀏覽器從既有公開村落入口驗證進場中點擊／弓箭不產生預測傷害、不呼叫攻擊API，抵達後即時傷害、合併、逾時原批重送、勝利及每日任務仍正確。合成時間前進以測試端正常服務回應同步客戶端時差，不跳動Phaser動畫時計；這是測試fixture接線，不是遊戲每擊新增網路請求。既有重載、商店倉庫、離場、公開圖片快取與固定舊版模組／worker升級也重跑。

**最終：671／671單元、11套共46／46真實Firestore／候選Rules、8／8不同瀏覽器流程通過。**核心流程初跑曾未真正等到抵達就攻擊，後續修正測試等待及合成時鐘同步，初跑失敗紀錄一併保留。完整數量與日誌見 `evidence/approach-guard-2026-11-28/validation-summary.json`；真實Firestore proof含當前原始碼hash。候選Rules測試不代表正式Rules驗收；iPhone實機／行動網路未測。

## 防作弊與舊版更新方案

見 [batched-combat-and-update-design.md](batched-combat-and-update-design.md)。已確立建議方向：

1. 保留本機預測與合併提交，以新版本協定驗證合法輸入／物理結果，不能把前端的hit=true當證據。
2. 弓箭驗證發射間隔、唯一箭矢與彈道碰撞，不直接把命中數限為每秒4次；多支箭可能集中命中。
3. 伺服器／前端共享確定性場地／運動／hitbox規則；處理低幀率與網路抖動，仍不每幀查Firestore。
4. 舊版先確認原經濟交易、保存原ID及payload，再提示更新及載入一致的module graph；純戰鬥不跨頁重播，含收蛋／偷蛋的複合請求不得清除。
5. 已開舊頁沒有更新監聽器，不能靠新API或worker魔術式升級；需橋接版與手動安全回退流程。更新UI、新輸入API、完整物理驗算尚未實作。

尚待產品／實測決定：節奏與burst契約、時間容忍窗口、可接受自動化操作風險、支援的最低客戶端artifact及更新UI。沒有用任意常數或自動封鎖規則代替這些決策。
