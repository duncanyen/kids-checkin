# 咕咕村落｜偷蛋成功彈窗

以 `preview.png` 為版面參考。預覽的雞名與數量是示例。

1. 沿用收蛋完成彈窗的容器、遮罩、捲動、安全區及關閉行為。使用 `assets/` 的獨立透明 PNG 與 `manifest.json`。手機畫面通常按版面寬度等比例縮放，較長的面板可沿用既有九宮格處理。
2. 載入成功結果後，在標題木牌覆蓋「偷蛋成功」。中央使用共用母雞插畫，雞蛋圖示已在金色總數底板內。行首留白，每列顯示母雞名稱、雞種與蛋數。
3. 用現有偷蛋流程實際扣除的來源紀錄產生明細。相同母雞個體的多顆蛋可合併，同雞種的不同母雞仍各佔一列。有公開名稱就顯示名稱，無名稱可顯示雞種與既有公開編號。兩項皆缺時可用「母雞 1」等本次結果的顯示序號，前提是結果仍能區分個體。
4. 如果現有偷蛋交易只回傳總數或雞種，從交易中實際選中的個體回傳可顯示的名稱、品種、數量及供前端分組的識別欄位。歷史結果實際缺少來源時顯示「來源未記錄」，不要從村落雞群或品種推測。
5. 以交易成功結果顯示總數與明細，確認入庫後顯示「已放入倉庫」。失敗及 0 顆保留遊戲原有提示。關閉及確定僅關閉彈窗，不再次執行偷蛋、發蛋或更新排行。保留原有偷蛋、倉庫及排行榜規則。
6. 長雞名可換行或省略，數量保持右對齊。多筆時讓明細區捲動並保持確認鍵可操作。測試同品種不同母雞、單一及多來源、缺少來源、入庫成功、交易失敗與小手機畫面。
